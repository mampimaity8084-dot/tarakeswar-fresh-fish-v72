# V4.3 Security Audit

Scope: isolated working copy only. No production access was used.

## Controls added or proposed

- Compatibility payment endpoints remain present.
- New payment flow is documented separately and is not wired into production.
- OTP metadata is additive and inaccessible to anonymous/authenticated direct table reads.
- Payment idempotency metadata is server/database-only.
- Customer image handling will use MIME validation, decoded-size validation, client compression, and server technical limits.
- Festival themes are data-only allowlisted values; no HTML, JavaScript, CSS, or URL execution is accepted from configuration.
- Admin and delivery authorization remain a V4.3 implementation target; production RLS is not changed here.

## Findings carried from V4.2

1. Broad authenticated policies require role/capability review.
2. `auto-banner.js` requires authenticated/internal authorization.
3. Push subscription insert/update policies require ownership controls.
4. Two payment implementations require consolidation after non-production tests.
5. Cloudflare error responses need safe public messages and correlation IDs.

## Safety gate

This candidate is not production-ready. It has not been deployed, connected to production Supabase, or tested against live Razorpay.
